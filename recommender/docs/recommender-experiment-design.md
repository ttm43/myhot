# 推荐系统 v1：LLM Judge（2026-10-16）

前两版（内容价值引擎、两层路径加三打分器）都推翻了。原因：过早发明评价理论，把单用户、小候选、异步的任务做成了通用引擎。这一版只做一件事：给定用户和文章，预测用户读完的反应。

## 核心

```
用户画像（configs/profile.md）
历史反馈（marks 表：label + note + 文章）
文章全文
        ↓
    LLM Judge
        ↓
牛逼 / 收到 / 无聊 + 0-10 分 + 理由 + 触发事实 + 置信度
        ↓
整批选择（看最近已推荐，去同质化，不设类别配额）
        ↓
当天清单：先看的 ≤15 条，然后完整池
```

不预设「技术增量、成本收益、新奇性」这类维度，模型自己决定对这篇、这个人什么重要。但理由必须指出文章里的具体事实并说明它和用户哪条偏好相连；指不出具体事实不能给牛逼。「用户做过 OCR 所以会喜欢新 OCR 模型」这种只有主题相关性的理由不算。

## 标签（和按钮一致，不改）

- niubi 牛逼：对我有用。
- received 收到：了解了，目前没有很喜欢，也算不上反感。默认档。
- boring 无聊：不关心。

（2026-10-16 用户重新定义。旧定义「想深入 / 早知道 / 有价值但不关心」作废；「早知道」需要模型知道用户的知识状态，判不出来。）

## 卫生规则（不是架构，不做就得不出结论）

1. 评测标签只存 `out/judge/labels/*.json`，不写 marks 表。画像、反馈例子、提示词调试都不读它。实验结束选定方案后才并入 marks。
2. 训练反馈 = marks 表现有内容（目前 11 条）。它们在评测集里保留但不计指标。6 条金标准不计指标，单独报全量排序里的名次。
3. 缓存键：`article_content_hash + profile_hash + feedback_snapshot_hash + prompt_version + model + body_cap`。任何一项变了就重打。
4. 输入冻结：每次全量跑记 run-meta（画像哈希、反馈快照、提示词版本、模型、token、时间）。
5. 触发事实要能在原文里找到（子串或模糊匹配）。找不到的降一档并标记。

## 两份评测集

| 集合 | 来源 | 用途 |
|---|---|---|
| DEV，约 80 篇 | 分层随机 70，约为池子的 13%（按来源分名额、来源内按周轮流、种子固定）+ 6 金标准 + 11 已反馈 | 错误分析、混淆矩阵、调提示词；标完后作为反馈池 |
| TEST，约 20–40 篇 | 全量排序 Top 20 加整批选择结果，合并去重，去掉已在 DEV 的 | 真实推荐效果，盲标（不显示分数和来源路径） |

DEV 是学习材料，TEST 是考卷。

## 消融（按顺序，不是同时）

| 实验 | 输入 | 验证什么 | 何时能做 |
|---|---|---|---|
| A | 画像 + 全文 | 画像本身能预测多准 | 现在，反馈只有 11 条时 A 就是全部 |
| B | A + 最近反馈 | 近期反馈改善多少 | DEV 标完（反馈约 180 条）后 |
| C | A + 检索到的相关反馈（正负例及原因） | 精选案例是否优于最近 N 条 | 反馈过 50 条后，用 AIHOT 已配的 Gemini embedding |
| D | C + 整批重排 | 能否去同质化并保持满意率 | 第一版就带上，但只在 TEST 上量 |

四组同一模型、同一批文章、同一套标注。B 对 C 没差别就不建反馈检索。

## 指标（按重要性）

1. TEST 上的 precision@10、@20。
2. DEV 上 niubi 的 recall 和 precision。
3. DEV 上三分类混淆矩阵。
4. 事实支持率：抽 30 条 niubi，触发事实在原文里找得到的比例。
5. Macro F1。
6. 6 条金标准在全量排序里的名次。
7. 成本：总 token、单篇平均。
8. 稳定性：DEV 抽 30 篇跑 3 次，label 翻转率和分数标准差。

DEV 只有 167 篇，precision@20 差两篇以内当噪声。

## 错误分析（有了 DEV 标签之后）

每条错判归到：没理解用户 / 没读懂文章 / 误用了负反馈（把主题当兴趣）/ 整批太同质。某一类反复出现才加针对性机制，不提前加。

## 工程边界

- 模型 gemini-flash-latest，temperature 0，照 scripts/skim.py 的调用方式。
- 候选池：AIHOT 库里 body_text > 500 字、且来源为启用的编辑源（participation_mode = editorial）的文章。2026-10-16 两轮信源清查后约 512 篇、35 个来源（清查依据 out/sources-triage.md）。全文，单篇上限 40000 字，按总字数分批（每批约 12 万字）。daily、TEST 表、金标准名次都只在这个池子里算。
- 一个脚本 `scripts/judge.py`，子命令：score、daily、sheet dev、sheet test、labels import、eval、stats。
- 不碰 skim.py、feedback.py、reality_check.py、push_catbus.py。

## 2026-10-16 结果

消融做完，结果和结论在 out/judge/error-analysis-2026-10-16.md。现行版本（2026-10-17）：提示词 v1.4 + 画像 v5（宽定义、严格规模规则）+ recent:20 反馈 + 事件去重 + 整批重排。第三轮结论：放松规模规则带来 3 篇误推，放宽定义单独不改变标签。反馈检索（C）暂不启用，等反馈过两三百条再测。
