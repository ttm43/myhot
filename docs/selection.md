# 精选

## 一条资料怎么变成精选

1. **收进来**：同一网址、同一内容只留一份。普通文章只有标题或摘要时，按信源规则补取正文；视频播放页使用已提供的文字材料，不把播放器页面当正文。没有可信发布时间的资料先不公开，读到原文日期后再判断新旧（见 [信源](sources.md#规则旧文不刷屏) 的“旧文不刷屏”）。
2. **预筛**（`prefilter.md`）：这是不是本行业的事。宽进，只拦明显无关的：`BLOCK` 的资料不出现在任何公开页面；`PASS` 和拿不准的 `UNKNOWN` 继续往下走。只有标题、没有正文、订阅摘要或帖子文字的普通文章先等待材料，不凭标题写文案，也不进入公开池；材料补齐产生新修订后再判断。可展示的空文字或纯链接原帖原样展示。
3. **结构化**（`structure.md`）：给出分类和标签（页面上显示的就是这一份）、主体公司，判断这篇是一条具体新闻、讲多件事的综合稿，还是材料不够、说不清；是具体新闻的，抽出它的事实（谁、做了什么、对什么、什么时候）和原文里的出处、前提条件。事件归组靠它。
4. **写标题摘要**：等结构化完成再写，按 `summarize-*.md` 写中文标题和答案先行的摘要，进“全部动态”。X 帖子没有正文或只含链接时，保留原帖的链接、图片和引用，不调用写作模型，也不生成“请补充正文”的文案；已经取得实际正文的 X 长文照常处理。
5. **入选**：程序不给资料打分，也不自己判断入选。一条资料进不进精选、卡片上显示多少分，由人工覆盖决定：后台“内容诊断”里改，或者外部评价器（`recommender/scripts/judge.py select`）通过管理覆盖接口写 `selected`、`score`、`reason`，必要时用 `relevance` 把预筛挡住的文章放进候选池。硬分叉之前按 AIHOT 评分选上的资料，分析结果里的入选和分数还留着，没有覆盖时照旧算数；资料出了新修订、重新分析以后，就只看覆盖。
6. **归组与去重**（`group-*.md`）：不同来源报道的同一件事归成一个事件。覆盖设为入选的资料要等归组完成才进精选：模型同时判断它和精选里已有的报道是不是同一条新闻，以及它有没有精选还没给过的具体信息。
   - 同一条新闻的几篇报道都可以入选：网页上折成一个阅读组；MCP 每条新闻只出一条，由代表报道出面：官方一手优先；其次是核实过的官方账号（填了 `publisherRole` 和 `owner_entity_id` 的 `T1_5` 账号，新闻的主体正是这家公司，机构先于个人）；再往后是有全文的、分数高的、发得早的。
   - 不是同一条新闻、但没有新信息的（换个说法再介绍一遍已经披露的能力、只是上架到别的平台、只重复已选要点的汇总），不进精选，留在“全部动态”；覆盖里明确写了入选的除外。讲多件事的综合稿不单独成事件，只挂到它提到的事件上；材料不够、确认不了是哪条新闻的，不进精选。
   - 显式撤回的报道保留历史归属，但不再参与之后的归组召回、候选代表、事件起点或自动事件比较；同网址及 X 回复／引用也不能借它提供身份依据。同一事实仍有有效报道时使用有效稿，全撤回则暂不召回；恢复公开后可重新参与。只展示摘要或尚未发布的记录不等于撤回，保留原有资格。已有关系和判断不删除，不批量重新归组。
   - 确认之前资料只在“全部动态”里，等得再久也不会自动放行。模型调用失败或回答不合格式，这条资料就停在那里：后台“运行”页列出这些资料，可以在后台“内容诊断”里打开这条资料，点“重新归组”。所以归组用的模型要能稳定按格式回答。

每一步的提示词都在 `industry/prompts/`，改提示词不用改代码。提示词的版本就是它内容的哈希：改了提示词，之后的新资料按新版判断，已经判过的不会重算。

`EXCLUDE_MP` 分级的信源不进精选，覆盖设了入选也不行。
